# A1 handoff — forge.agents (plugins/93-agents.js)

## Works (tests/t_agents.py: 21 PASS, FAILS: none, on `build.py --only 60-providers,93-agents,95-picks`)
- Roles: orchestrator, coder, researcher, reviewer, fast, plus user-defined ones. Each has {provider, model, prompt, tools groups, maxSteps} and is saved in ctx.data (survives a reload). Settings section "Agents · roles & models" and an Agents view (org-chart icon) with a model select built from usable models only, a Test button that makes a real stream call, add/delete role, and a max-parallel setting (default 3).
- Tools: `spawn_subagent {task, role?, tools?, wait?}`, `agents_wait {ids?, timeout_s?}`, `agents_status {}`. Each child thread has hidden=true, parentId, agentRole and route taken from its role (falls back to the parent's route, else the global model). It also gets the parent's permission tier, a step cap from a beforeModel hook (tools=[] once the cap is hit, then stop), a 5-minute budget and a concurrency semaphore. Results are {role, model, answer, tools_used, files_changed}, and the child's file changes are copied into parent.changes so they can be reverted there.
- Orchestrate pill (toggle `agents-orchestrate`): adds an ORCHESTRATOR system prompt. If the Orchestrator role has a provider, it sets main thread.route on run:start or on toggle, and restores the old route when the toggle is turned off.
- Live panel: emits `agents:update` events; shows Stop and Open thread (read-only sheet, with "Un-hide & open"); also lists subagents from earlier sessions after a reload.
- Sim: the `orchestrate: …` / `use subagents to …` intent spawns 2 subagents (wait:false), then agents_wait, then a summary. Sim allows one tool per step, so this takes 3 steps. A child-task intent (order 1) answers Sim children. Suggest card "Split a task across subagents".

## Core issues for main agent
1. Sidebar (src/js/70-ui-shell.js ~l.114) does not filter `t.hidden`. Stopgap: 93-agents injects `.th-i:has([data-t=ID]){display:none}`. Please filter `Store.threads().filter(t => !t.hidden)` in the sidebar and in the boot fallback (80-boot.js l.12).
2. `DS.agent.stop(child)` calls `Guard.cancelPending()` and resolves *all* `asks`. Stopping one subagent can cancel the parent's pending approval or ask_user. It should be scoped to the thread.
3. The agent loop runs a step's tool calls one after another (`for … await`). Several spawn_subagent calls in one model step therefore run one at a time unless wait:false + agents_wait is used. The orchestrator prompt says so. Promise.all over a step's calls would fix it.
4. The Sim's `sctx.thread` is the active thread, not the one streaming. `stream()` receives `thread`, so passing it into sctx would let intents tell child threads apart.
