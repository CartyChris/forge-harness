# A3 handoff — Continue.dev compatibility — DONE
Files: `plugins/67-continue.js` (forge.continue v1.0.0), `tests/t_continue.py` (44 checks; passes on the `--only` bundle and the full build; t_core also passes on the full build).

## Works (tested, all mocked offline)
- `forge.continue.parse(text)` takes config.yaml or legacy config.json. The YAML-subset parser handles maps, lists, `- k: v` items, quoted and plain scalars, `|`/`>` block scalars with chomping, one-line flow `[..]`/`{..}` and comments. It rejects anchors, aliases, tags, `<<` merges, tabs and multiple documents, with a line number in the error.
- Import preview sheet → Apply:
  - Known providers go to the catalog (key set with `setKey`). An unknown `apiBase` creates `forge.models.custom.add` (tagged unverified).
  - `free-trial`/`continue-proxy` models are skipped and the preview says why.
  - `${{ secrets.X }}` asks once through `DS.ui.promptText`. A placeholder is never stored as a key.
  - Roles: chat→main (selected; there is a checkbox to opt out), edit/apply→coder, autocomplete, summarize→fast, embed is only recorded. They are stored in ctx.data and returned by `forge.continue.roles()`. If `forge.agents.setRole|setRoleModel|assignRole` exists, it is called too (untested: the service doesn't exist yet).
  - Rules go into `/AGENTS.md` under `## Rules (from Continue)`. Running it again replaces that section instead of adding a second one.
  - Prompts become `/name` commands that send the prompt plus the user's args. If the name is already taken, the command becomes `/c-name`.
  - MCP http/sse servers connect through `DS.mcp.connect` and are saved to `settings.mcp`. stdio servers connect only if `DS.bridge.status` looks online; otherwise they are listed as "needs the local bridge".
- `exportYaml()` writes keys as `${{ secrets.<PID>_API_KEY }}` placeholders and never the real keys. The output parses back cleanly.
- `complete({prefix,suffix,lang,signal})` uses the autocomplete role through `providers.core.streamFor` with a FIM prompt. It strips fences and overlap with the prefix/suffix, and caps output at about 800 chars (it aborts the stream). `autocompleter({delay}).request()` is debounced and cancels itself: a superseded request resolves to null. A plain `debounce` is also exported.
- Settings → "Continue.dev" has import/export/copy buttons, the role table with Clear, the prompt list and the honest note. There is also a `/continue [export]` command, the Sim intent and the "Import my Continue config" suggest card.

## Untested / notes for main agent
- stdio connect through the bridge (no bridge in the sandbox). Hub `uses:` blocks are not fetched; the user gets a warning.
- `complete()` goes through `streamFor`, so it calls setIdentity: the "current model" identity briefly shows the autocomplete model. A core option to skip identity would fix this.
- No role picker UI for setting roles by hand yet (only import and Clear). `setRole(fr, {provider, model})` exists in the API.
- IDE wiring is not done (main agent's job): call `forge.continue.autocompleter().request({prefix, suffix, lang})` from 42-ide.
- Anthropic without apiBase uses `https://api.anthropic.com/v1` (OpenAI-compat layer). It is unverified from a browser and probably blocked by CORS.
