## Batch 6 (router + CaMeL details)
- freellmapi router internals (instagit code explainers; verify in repo) [V-secondary]:
  - Retryable = 429 + 5xx (server/src/lib/error-classify.ts). Penalty per 429 = +3, cap 10, decays every 2 min; priority mode sorts chain by priority+penalty (router.ts orderChain/getPenalty/recordRateLimitHit).
  - Key eligible if health healthy|unknown, not on cooldown, passes RPM/RPD/TPM/TPD + provider daily cap (ratelimit.ts canMakeRequest/canUseTokens/canUseProvider). Cooldown on 429/402/403, ESCALATING 2m -> 10m -> 1h -> 24h by throttle count in last 24h (getNextCooldownDuration). Parses provider quota headers (provider-quota.ts). Chain exhausted -> 429 RouteError. Filters chain by vision/tools/context-window before key pick.
  - Port to Forge (client-side, IDB instead of SQLite): exactly this: sliding-window counters per key+model, escalating cooldown ladder, decaying penalty, capability filters, parse x-ratelimit-* headers.
- CaMeL (arXiv 2503.18813) per Simon Willison [V-secondary]: P-LLM (tools, never sees untrusted text) writes restricted-Python plan; Q-LLM (no tools) extracts from untrusted text into variables; custom AST interpreter tracks dataflow; capability tags (readers + provenance) on every value; policies (e.g. send_email only to trusted recipient else ask user). No repo link on that page (google-research/camel-prompt-injection exists per memory — unverified). Port: Forge plan-then-execute mode with JS-subset plan (acorn AST walker) + taint tags.
